## 1. Web App Architecture
The Cast Recruiter web app is a **Visual Card Grid Builder** deployed via `clasp` to Google Apps Script. 

### Key Features:
* **Unique ID Support:** Extracts the `ID (str)` column for characters, loyals, talismans, and specials from the backend sheet, serving them to the client as `uniqueId` properties.
* **Dual-Format Export:** The export handler in `CastRecruiter.html` outputs a highly structured JSON:
  * `championId`: String
  * `unitIdsRecruited`: Dictionary `{ uniqueId: qty }`
  * `talismanIdsEquipped`: Dictionary `{ talismanUniqueId: "Attached to: familiarUniqueId" }`
  * `specialIds`: Array of unique ID strings
  * **Backward Compatibility:** Retained all legacy keys (`champion`, `unitsRecruited`, `talismansEquipped`, `specialActions`) so older parsers still work seamlessly.

## 2. Tabletop Simulator (TTS) Importer
The TTS Importer has been fully upgraded to handle secure, foolproof unique ID-based loading and completely bypasses layout zone physics bugs.

### Upgraded Script Architecture (`tts/TTS_Loader.lua`)
* **Metadata Injection (The Scraper Fix):** 
  * The Python script (`dextrous/generate_card_images.py`) parses the CSV data files (`M3_TTS_DB - IN Cha-Tal.csv` and `M3_TTS_DB - IN SP.csv`) and automatically injects:
    1. Human-readable Name -> Injected into the visible `"Nickname"` field.
    2. Unique ID -> Injected into the invisible `"GMNotes"` field.
  * This allows players to hover over cards in TTS to see their actual names while scripting can securely identify them by ID!
* **Robust ID-Based Lookups:** 
  * `cloneCardFromDeck` checks if the deck metadata's `gm_notes` matches the unique IDs in the pasted JSON.
* **Instant Teleportation Return Physics:** 
  * When cloning, the script briefly pulls the original card out of the deck, clones it, and then puts the original card back.
  * To prevent the original card from colliding with table elements and failing to return, the script *instantly teleports* the card back onto the deck (`cardObj.setPosition(deck.getPosition())`) right before `deck.putObject(cardObj)`. This guarantees 100% absorption and zero duplicates on the table.
* **Unified Hand Dealing (The Layout Zone Fix):**
  * Spawning cards directly onto layout zones often failed because the physics engine merged them into a deck before the zone could align them.
  * The Champion, exactly **1 reference card** per recruited Familiar/Minion, Talismans, and Special Actions are all dealt directly into the player's hand.
  * This is clean, fast, and gives players absolute control to layout their cards manually without layout-zone interference.
* **Unity Reference Safety:**
  * To resolve `NullReferenceException` errors ("Object reference not set to an instance of an object"), the script re-queries the trigger zones to find the active deck references fresh on every single loop iteration.

## 3. Workflow for Content Updates
When adding new cards or modifying sheets:
1. Export the latest Saved Object JSONs from Dextrous to the `dextrous/` folder.
2. Run `python dextrous/generate_card_images.py`. This will:
   * Scan your sheets/CSVs.
   * Inject Names into Nicknames and Unique IDs into GM Notes for the TTS Saved Object JSONs (automatically generating deterministic `SYN-` prefix unique IDs for any items missing IDs in your sheet, such as Loyal Companions or Talismans, ensuring all cards successfully resolve!).
   * Regenerate `CardImages.gs` with image sprite coordinates.
3. Use `clasp push` to sync your GAS backend.
4. Import the newly saved JSON Saved Objects in Tabletop Simulator. All cards will be fully searchable, layout-safe, and ready for deployment!

## 4. End Game UI & Webhook Submission
We have implemented a decoupled, 3D button-based End Game Controller to record match results and balance statistics, keeping the Cast Loader and End Game functions modular.

### Architecture & Components:
* **Cast Loader API (`tts/TTS_Loader.lua`)**:
  * Captures successfully loaded player casts globally (`loadedCasts`).
  * Maintains a chronological log of Special Actions (`specialActionsLog`) via a global function `logSpecialAction(playerColour, cardName, cardId)`.
  * Exposes this match data securely via a global API function `getMatchDataJson()`, which returns a serialised JSON string. This completely bypasses Tabletop Simulator's cross-script table ownership limitations ("Attempt to perform operations with resources owned by different scripts").
* **Dedicated End Game Controller (`tts/End_Game_Controller.lua`)**:
  * Attached to a separate, dedicated table token (e.g. your red/yellow brand tile).
  * Reduces table clutter by drawing a single central, static tactile 3D **"End Game"** button (Green background) that never changes.
  * Restricts interaction to the Host.
  * Clicking **"End Game"** triggers a gorgeous, floating **XML UI Pop-up Panel** directly above the token:
    * **Red Won** (Red)
    * **Blue Won** (Blue)
    * **Draw** (Grey)
    * **Cancel** (Dark grey, closes the panel without declaring a winner)
  * Clicking any winner option immediately closes the pop-up, retrieves match data from the Cast Loader via Tabletop Simulator's `call` API, compiles/serialises it, and automatically POSTs it to the configured Google Web App.
  * Explicitly uses Tabletop Simulator's positional `WebRequest.custom` API with standard `Content-Type: application/json` headers to guarantee the server-side Apps Script parses the raw body successfully and fully populates all columns.
* **Webhook Receiver & Sheets Integration (`webapp/main.gs`)**:
  * The `doPost(e)` function in the Apps Script backend has been upgraded into an ultra-resilient parser.
  * It logs match records live to a spreadsheet tab named **`IN TTS`** (creating it on the fly if it is missing) using sequential appending via `sheet.appendRow()`.

* **Implementation:**
